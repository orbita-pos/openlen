<h2 id="la-puerta">The gate that never opened</h2>

Len can propose a goal for your page —“get this page more phone calls”— and pursue it if you approve the card. We had an uncomfortable number: <Cifra valor="0 of 104" commit="4d34223e">real projects with an active goal</Cifra>. We also had a reasonable hypothesis for why: people don’t understand the feature, so they don’t use it.

The hypothesis was wrong. Testing the feature end to end against the real server showed that **the half that did exist didn’t work either**. The code that knew how to save a goal had known since day one; but the validation that runs *before* it —the one that decides whether the request continues— didn’t have that key in its allowlist. Every goal write returned 400 without ever reaching the code that knew how to apply it. <Fuente commit="4d34223e" />

Nobody saw an error. There was nothing in the console. Just a feature that, from the outside, looked like one users didn’t want.

<h2 id="el-patron">The pattern</h2>

The interesting part isn’t the bug: it’s its shape. One decision —“which keys do I accept?”— written in two places, and one of them falls behind.

We found the cleanest version of that shape in the chat. The question “did the page change this turn?” was computed in **two** places in the same file, with different conditions and forty-six lines between them: one for what you see live, one for what gets saved. The correction that fixed the condition only reached the first. The result: what you saw live and what you saw after a reload disagreed, **in both directions** — a turn that hadn’t moved a byte got its “Undo” button back, and a turn that had changed something durable lost its notice. <Fuente commit="e283f46d" />

The fix has a name, and it’s a rule rather than a patch: **extract, don’t copy**. Copying leaves two again, and the next correction reaches only one of them. When extraction isn’t possible —because they genuinely are two different questions— what ties them together is a test.

Both end the same way: the rule gets **executed** instead of begged for. In the first, the loader that avoids the opaque origin now exists exactly once — the fix already existed in another renderer and simply hadn’t reached this one, the same pattern as always. In the second, a delete or a replace must now target something the model *has seen* this turn; and whatever gets discarded is reported, in whole or in part, because losing an operation silently is the degradation this repository forbids.

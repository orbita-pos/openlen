## r/webdev

**Title:** Built an AI landing-page builder that outputs static HTML (no React runtime on the published page) — some technical notes

**Body:**

Sharing the architecture of a side project (**OpenLen**) because a couple decisions might be useful / worth arguing about.

The core constraint I set: **published pages are plain static HTML**. No client framework, no Node hop at request time. AI (Gemini) generates a complete HTML document, the user edits it, and on publish it gets written to disk and served straight off the web tier (Caddy). Tailwind comes in via CDN. A typical published page is just… an HTML file. Fast, cacheable on Cloudflare's edge, nothing to hydrate.

A few things that were trickier than expected:

- **In-iframe inline editing without breaking layout.** I didn't want to make the whole DOM `contenteditable` (kills `text-wrap: balance`, fights with transforms). So text gets hidden and a plaintext-only overlay floats on top, position-corrected for transformed/fixed/absolute elements. The page DOM never becomes editable.
- **Section library that color-matches.** Inserting a "pricing" section from a library is easy; making it not clash with the host page is the hard part. CSS is scoped per-section (`:root` → `[data-sec]` at build time via PostCSS), and a "match to page" step recolors the section's scoped styles to the host palette.
- **Keeping the AI output honest.** There's a reserved editor-mode marker (`data-slot-path=`) that must never reach disk — every ingestion path rejects it. Defense in depth so an editor artifact can't end up on a live page.

Stack: Next.js (App Router, standalone) self-hosted on a single Hetzner box, Postgres (Neon), Caddy, R2 for assets. Deliberately no Redis/queue until there's a real trigger for one.

Not trying to pitch it hard — happy to go deep on any of these in the comments. Curious how others handle the "make AI output editable but keep it semantically clean" problem, because that was the rabbit hole I underestimated most.

1. **Ship the page before it's perfect, then iterate on real traffic.** A live "good enough" page you can put in front of people beats a perfect page that's still in your head. You learn nothing from a draft.
2. **Your landing page's job is one decision, not ten.** Most early pages try to say everything. The ones that convert make a single offer crystal clear and have one obvious button.
3. **Don't outsource the part you'll edit weekly.** A $2k freelancer page is great until you need to change the headline and have to email them. Own something you can edit yourself in 30 seconds.

The tool is **OpenLen** — describe a page, AI builds it, edit it, publish to a live URL in one click ($3.99/mo, free tier to try). But honestly the takeaways above are the point. The biggest unlock for me wasn't the AI, it was removing the excuse to not ship.

**Title:** A section library that auto-matches your page's colors when you drop a block in — finally

**Body:**

The thing that's always annoyed me about no-code builders: you find a nice pre-made section (pricing table, FAQ, testimonial wall), drop it onto your page, and now it looks like a ransom note. Different fonts, clashing colors, wrong corner radius. Then you spend 20 minutes manually fixing it, which kind of defeats the point of a pre-made block.

I built a builder (**OpenLen**) and the feature I most wanted to get right was exactly this: you browse a section library, preview a section, click "use on my page," and it **auto-recolors to match the palette you already have** before it lands. No manual restyling.

How it works for the non-technical: each section ships with its own self-contained styles, and when you insert it, it adapts to your page's colors/accent instead of importing its own. So a dark pricing section becomes a *your-brand* pricing section.

10 languages, free tier (20 credits/mo), $3.99 Pro.

# 3) SHOW HN

**Title:** Show HN: OpenLen – Describe a landing page, get static HTML, publish in one click

**Blurb:**

I wanted to go from "idea" to "live landing page" in minutes without a weekend of fighting a builder. OpenLen takes a plain-English description and generates a complete landing page (via Gemini), which you can edit inline, then publish.

The design constraint I care most about: **published pages are plain static HTML** — no client framework, no Node at request time. AI generates a full HTML document, it's written to disk, and served straight off the web tier (Caddy) with Cloudflare in front. Tailwind via CDN, nothing to hydrate.

A couple of the harder problems: in-iframe inline editing without making the DOM `contenteditable` (text is hidden behind a position-corrected plaintext overlay so `text-wrap: balance` and transforms survive), and a section library where inserted blocks have their scoped CSS recolored to match the host page's palette.

Self-hosted on a single Hetzner box (Next.js standalone, Postgres, Caddy, R2) — deliberately no Redis/queue until there's a reason. Free tier to try; Pro is $3.99/mo. Happy to go deep on the architecture, and very open to feedback on the approach.

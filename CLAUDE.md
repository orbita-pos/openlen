# OpenLen — repo-level instructions for Claude Code

OpenLen is a landing-page builder — and, since 2026-10-07, a builder of **web apps** too (see the app row of the table and invariant 6). Users describe a page (or pick a template, or paste their own HTML), edit, and publish to `<sub>.<publish host>` — the host is `PUBLISH_BASE_HOST`, and **production has been `openlen.app` since 2026-08-23** (⚠️ **only `.app` serves pages since 2026-09-10** — `61cec120` narrowed the Caddy wildcard to `*.openlen.app` and `*.openlen.com` now just 308-redirects there; this line used to say the two served the same folders, and that staleness already cost one wrong code comment. `.app` is a separate browser origin, which is the point). Never hardcode either — `lib/publish/base-host.ts` is the single source. The repo runs as a Next.js app self-hosted on Hetzner — **never Vercel**. Brand was renamed from "Inari Pages" on 2026-05-16; `Inari Watch` is a separate sister product (monitoring, not pages), don't conflate.

## Architecture invariants — do not break

1. **Templates are HTML files, not React components**. Each template is pure HTML (Tailwind CDN + Google Fonts inline) — its body lives in object storage, its metadata in Postgres. Do NOT port them to TSX — we tried, the user rejected it. Add a new one with `npm run templates:add` (see the Template gallery section); never by dropping files in the repo or editing a registry.
2. **Templates never claim subdomains**. Only user projects do, at publish time. `mirror.html` is inspiration; `<myco>.<publish host>` is what a user gets after cloning Mirror + clicking Deploy.
3. **The published DOCUMENT is static HTML**. `project.data.html` → `/var/www/openlen/<sub>/…` → **Caddy** serves it straight off disk. No React runtime and no Node in the render path; Tailwind via CDN is OK. ⚠️ **"No Node hop" is no longer absolute**: the published page calls back for the backend features — `/c/*` (analytics beacon), `/api/f/*` (form submissions), `/api/chat/*` — which Caddy reverse-proxies to Next from inside the same wildcard block. The page RENDERS without Node; it INTERACTS with it.
4. **`publishToDir` rejects HTML containing `data-slot-path=`** — a reserved editor-mode marker. The `from-html`, `from-template`, and `ai-design` paths reject it too (defense in depth) — it must never reach disk or the DB. The OTHER editor marker, `data-op-id`, is **stripped, not rejected** (`stripOpIds`): a slot-path means the document came from a pipeline that no longer exists, while an op-id is an inert attribute on an otherwise correct page — rejecting it would punish the user for an upstream bug of ours.
5. **La terminal de Len interpreta, no ejecuta** (`lib/agent/terminal/`, F1 de `plans/len-agente-2026`; encendida por defecto desde el 03/10, como en DeepSeek: sólo `OPENLEN_TERMINAL=0` la apaga): no crea procesos, no toca el disco del servidor ni la red; sus ficheros son los del proyecto, y todo lo que escribe entra por las mismas guardas que `Write` (`guardarLoDeLaTerminal` → `aplicarPlan`). Es `just-bash` en un `worker_thread`, nunca en el hilo de la app. Lo que el modelo lee de un comando es lo del `Bash` de Claude Code (desde el 2026-10-09; antes, la línea de DeepSeek `[Command finished with exit code N]`): la salida sola si no falla, `(bash completed with no output)` si no hay, y si falla —con la regla de su binario: `grep`/`find`/`diff`/`test` fallan del 2 en adelante— `Exit code N` arriba y la salida recortada por el medio a 10.000; el código va además en `exitCode` de la respuesta para la lente. Sus tiempos y su salida larga son los del `Bash` de Claude Code (plan 04 de las apps, tarea 7, leídos en su binario 2.1.293): 120 s por comando, `timeout` hasta 600 s; al pasarse, «Command timed out after 2m 0s» DELANTE de lo que alcanzó a escribir y código 143 (lo de antes del corte `just-bash` 3.6.0 lo tira; lo de `npm test` se guarda), y lo que arrancó el comando —empaquetar, Chromium— acaba con él; más de 30.000 caracteres van enteros a `/tmp/tool-results/N.txt` (no es del proyecto) y el modelo recibe `<persisted-output>` con la ruta y una vista previa. `npm test` en una app pide al hilo de la app correr las pruebas en el Chromium de los ojos, como `view_page`: la terminal sigue sin crear procesos. Cada comando queda grabado como cualquier herramienta (la llamada en la grabación, su salida en la transcripción del turno). Un `bash` real con procesos sería otra máquina (F7), nunca la de producción.
6. **En una app, el compilador es la ÚNICA PUERTA de los fuentes** (`lib/apps/compilador.ts`). El lienzo (`/api/lienzo/site` → `servirRutaDeLaApp`), los ojos de Len (`view_page`, `use_page`) y la publicación (`publishToDir` → `compilarCarpeta`) usan el mismo: ninguno sirve un `.jsx` sin pasar por él, y los tres reciben el MISMO paquete (`lib/apps/bundler/`, esbuild-wasm en su hilo): la app es UN fichero en su entrada con sus fuentes y sólo lo que usa del catálogo; el lienzo y los ojos, con React de desarrollo y su sourcemap; la publicada, de producción y minificado. Un fuente que no compila: en el lienzo, un módulo que lanza su error con fichero y línea; a Len, un `<new-diagnostics>` en el acto (`lib/agent/compila-la-app.ts`); al publicar, **la publicación se niega** (y `publish` se lo dice a Len antes de la tarjeta). Lo que se importa sale SÓLO del catálogo del proyecto, empaquetado; no hay npm. Si el empaquetador no contesta, el lienzo lo dice en un módulo que lanza y la publicación se niega. Len en una app tiene su prompt, su manual, su guía y sus herramientas (`lib/agent/modo-app.ts`): `view_page`/`use_page` llevan `screen`, `undo_last_change` deshace el turno anterior ENTERO (`lib/projects/deshacer-turno.ts`) y `publish` va sin idiomas. Una app NACE del esqueleto con el primer mensaje (`naceComo: "app"` → `lib/projects/nacer-como-app.ts`) y una página SE CONVIERTE en app en un turno (`convert_to_app`, `lib/agent/convertir-en-app.ts`: Len escribe `/src` con la página intacta y la herramienta voltea de una vez; si `/src` no compila, no convierte nada). En una app el lienzo la enseña corriendo y **no se edita a mano** (ni lápiz, ni soltar, ni elegir elemento), y no hay traducción automática.

## Workspace V2 mental model

`/new` derives its state from URL params. `EntryMode` is
`"ai" | "template" | "paste" | "editing"` — **there is no `choosing` state and no
3-card chooser screen**; that was replaced by the start landing.

- **no params** → `ai`, only for an instant: it opens (or reuses) the user's blank project (`POST /api/projects`) and redirects to `?project=<id>`. There the chat's empty state (`start-landing.tsx`) is the entry, and sending is the first message to Len. Above its composer, two cards choose **Página** (default) or **App** (`tarjetas-nace-como.tsx`); with App, that first message carries `naceComo: "app"` + `idioma` and the blank project gets the app skeleton before the turn, and the gallery and «paste HTML» hide (they are page things). A brief in the URL (the marketing hero, an old `autostart=1` link) only FILLS the composer, never sends. Template and Paste are reached from the sidebar tabs, not from a chooser.
- `?mode=template` / `?mode=paste` → that guided flow.
- `?project=<id>` → `editing` → the full workspace.
- `?view=` picks what the CENTER renders, with a project open or without: `projects` · `explore` · `templates` · `messages` · `resultados` (`analytics` is its old alias) · `database`. Absent = the page canvas. ⚰️ `business` (2026-08-31), `modulos` and `marketing` (2026-10-08, to be rebuilt better) are gone: their old links fall back to the canvas.
- `?page=<slug>` picks WHICH site page the canvas shows (multi-page).

On submit the empty state uploads the photos (`/api/upload`) and sends the first message to `/api/agent`; the canvas paints the page while Len writes it (`page_preview` events). **In an app** (`loadedProject.app`), the canvas shows it running from the lienzo host, with no visual editing; the Code lens comes FIRST and the preview lens is called «App»; the address bar has no pages; and when the real canvas doesn't answer it says so (locally there is only the shell, which starts nothing). The blank project stays out of the projects list until it has something. (`useGeneration` → `/api/generate` was retired on 2026-10-06.)

The sidebar locks tabs per entry mode — in an entry flow only the relevant tab is interactive; in `editing` every tab opens. A project is flat HTML: `data.html` is the Home, plus `data.pages` (slug → `SitePage`) when the site has more pages. There is no slot-based project type — generation is free-form. The Content tab activates in-iframe editing (inline-edit + section reorder + asset replace); the Chat tab redesigns the page end-to-end.

## Template gallery — DB-backed (since 2026-05-18)

Curated templates are **not individual files in the repo**, and there is **no `components/templates/_registry.ts`** (that file was deleted). The gallery is database-backed:

- **Metadata** in Postgres — the `templates` table (`id` = slug = PK; name/family/accent/pitch/description/mode/status + storage fields).
- **HTML bodies** in object storage — R2 in prod (public via `templates.openlen.com`), a local FS fallback in dev (`public/template-objects/`, gitignored). Object path: `templates/<id>-<contentHash>.html`.
- **Server store**: `lib/templates/store.ts` — `listTemplates`, `getTemplate`, `upsertTemplate`, `getTemplateHtml`, `archiveTemplate`.
- **Client-safe types**: `lib/templates/families.ts` — `TemplateFamily` union + `TEMPLATE_FAMILY_META` (zero node imports, safe to import from client components).
- **Zod schemas**: `lib/templates/admin-schemas.ts` — shared by the admin API routes and the CLIs.
- **Public API**: `GET /api/templates`, `GET /api/templates/[id]`. The `/new` gallery reads through these (`components/workspace-v2/use-templates.ts`).
- **In-repo starter pack**: `templates/starter/` — 3 HTMLs (mirror, manuscript, counter) + `manifest.ts`, uploaded by `npm run templates:seed` so a fresh clone boots with a non-empty gallery.

**Adding a template** — run the CLI, never touch the repo:

```bash
npm run templates:add -- <file.html> --id=<slug> --name="<Name>" --family=<slug> \
  --accent=#RRGGBB --mode=<dark|light|cream> --pitch="<hook>" --description="<sentence>" --status=published
```

It validates against `admin-schemas.ts` (rejects `data-slot-path=`), uploads the HTML to storage, and upserts the DB row. Do NOT drop `.html` files into `public/templates/curated/` and do NOT create a `_registry.ts` — neither registers anything; the gallery never sees them. Other CLIs: `templates:republish` (re-upload HTML after edits/renames), `templates:count` (verify DB + storage state).

**Adding a new family** — add the slug to BOTH the `FAMILY` z.enum in `lib/templates/admin-schemas.ts` AND the `TemplateFamily` union + `TEMPLATE_FAMILY_META` in `lib/templates/families.ts`. The DB `family` column is plain `text`, so no migration.

**Design briefs** for new templates live in `docs/claude-design-prompts.md` — prompts run in claude.ai, each producing 5–6 landing-page HTMLs that are then registered via `templates:add`. Related brief files sit beside it (`claude-section-prompts.md`, `claude-layout-variant-prompts.md`, per-family design briefs and image prompts).

Community pages **are built**, just not the way this file predicted: there is no `community_templates` table. **Explore** (`/explore`, `app/api/explore/`, `lib/community/`) lists ordinary `projects` rows with `visibility = "public"` and `status = "published"`, joined to the author's `users.handle` — a published page becomes public, it does not become a template. Public profiles live at `/[handle]`, and remixing is counted on `projects.remixCount`.

**Design surface philosophy.** The three original surfaces are the **Chat tab** (open-ended AI editing), the **Content tab** (in-iframe text editing + section reorder + asset replace), and the **inspector** (`panels/properties-panel.tsx` — per-element properties + global radius/font/accent). ⚠️ **"Three places" undersells it now**: `components/workspace-v2/panels/` also holds modules, collections, site-pages, images, versions, submissions and insights panels, each a real surface.

**The Chat tab talks to `/api/agent`, not `ai-design`** — the agent graduated and is the default; `ai-design` is the opt-out. Reading the older comment at the top of `chat-panel.tsx` and believing it is a known trap.

**Who runs what — `lib/generation/model-policy.ts` IS the answer, and it is a table.** **Three** roles (`reasoner`, `visualCritic`, `agent`) — `designer` was retired on 2026-09-06 along with the four operations that had zero callers (`creative_direction`, `page_planning`, `initial_section_program`, `visual_repair`), leftovers of two deleted pipelines; a guard (`model-policy-sin-huerfanas.test.ts`) now fails if an operation in the table has no caller. Every surface names an OPERATION and the table picks the role, the model and the reasoning effort. 🔴 **Never restate a model name in this file** — that is exactly how the previous version of this line went stale and then misled a session into "reasoning" from it instead of from the code. Read the table.

**Gemini is OUT — of all four roles, since 2026-08-28.** Everything runs on Fireworks. The three provider switches (`OPENLEN_GENERATE_PROVIDER`, `OPENLEN_CHAT_PROVIDER`, `OPENLEN_AGENT_PROVIDER`) were deleted with it, as were `OPENLEN_AGENT_EYES=gemini` and `OPENLEN_CREATE_EYES=gemini` — not kept switched off, deleted, because a lever pointing at nothing reads as an alternative that exists. The Rust `ai-gateway` crate has no Gemini transport at all. ⚠️ **Four surfaces outside the policy table still hardcode `gemini-*` default model strings** — `lib/imagery/photograph.ts`, `lib/publish/localize.ts`, `lib/style-match/autofill/fill-from-page.ts`, `app/api/assistant/[sub]/route.ts`. They are leftovers of the cleanup (each rolls its own default instead of asking the table), NOT evidence that Gemini is still wired.

**The Canva-mode pivot was rolled back on 2026-05-24** — see [[canva-mode-decision]] memory for the full reasoning. Short version: the document-model engine (`lib/doc/*`) and the structured Canva inspector worked in principle but the conversion of polished HTML templates lost too much visual fidelity (animations, custom CSS, brand SVGs all stripped). User prefers the HTML visual quality. Everything related (`lib/doc/`, `components/workspace-v2/model/`, scripts/templates-convert-*, ai-edit endpoint, document-mode flag) was removed. The born-canonical normalizer (`lib/normalize.ts`, `normalizeBornCanonical`) is the ingestion path — `from-html` + `from-template` produce plain HTML projects (and so did `generate`, retired on 2026-10-06). ⚠️ **Dónde corre, medido el 2026-09-05:** en `document-gate.ts:208`, y sólo cuando `policy.normalize !== false`. Las superficies del modelo (el Chat y Len; Crear también, hasta el 2026-10-06) entran por `lib/page-engine/prepare.ts`, que pasa **`normalize: false`** — a lo que escribe el modelo NO se le normaliza. Lo llaman directo, además, las rutas de comunidad (`lib/community/seed.ts`, `store.ts`). ⚰️ Esta línea decía que **`lib/projects.ts` lo corre a la entrada**: lo importaba y no lo llamaba (import retirado el 2026-09-05). Downstream of it, `lib/page-engine/` is the shared pipeline (prepare → apply edits → persist) used by the Chat and the Agent alike. **Do not propose Canva-mode revival without explicit user request.**
